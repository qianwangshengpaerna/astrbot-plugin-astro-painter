# AstroPainter · AstrBot 生图插件

给 AstrBot 接上任一生图模型。说一句「帮我画只猫」就出图，不用记指令；先发图再说「改成水彩」，直接走图生图。

只做静态图片，不包含视频生成。输出画布默认压在 720p 以内，默认全站每天总共只能出 5 张（可改成每群 5 张）。

## 特性

- **三种触发方式，不漏单**：LLM 工具调用 / 指令 `/画图` / 全消息意图识别（不依赖 function calling）
- **两种协议**：OpenAI Images（`/images/generations`、`/images/edits`）与 Chat Completions（图片藏在回复里也能解析）
- **画布封顶**：请求按 720p 下发，厂商返回大图也会被本地等比压到上限内，不占流量也不超分辨率
- **提示词引擎**：对话模型以「画师」身份接单，有自己的构图和风格主张，把「画只猫」变成完整作品方案
- **画师记忆**：记得上次给这个人画了什么，可以延续风格，也可以刻意换一个方向
- **成本闸门**：额度池默认 5 张/天，作用范围可选全站 / 每群 / 每人，另有单用户冷却、全局并发上限、多 Key 轮换、429/5xx 退避重试
- **体验**：横竖屏自动识别、失败原因翻译成人话、可选附带提示词、改图自动取引用消息里的图
- **只依赖 httpx + Pillow**（后者用于画布压缩，AstrBot 环境已自带）

## 安装

**方式一：插件市场（推荐）**
AstrBot WebUI → 插件 → 插件市场 → 搜索 `AstroPainter` → 安装 → 重载。

**方式二：手动**
把整个 `astrbot_plugin_astro_painter` 文件夹放进 `AstrBot/data/plugins/`，然后在 WebUI 插件页点「重载插件」。

**方式三：git clone**

```bash
cd AstrBot/data/plugins
git clone https://github.com/qianwangshengpaerna/astrobot-plugin-astro-painter
```

安装后在插件卡片上点齿轮配置，填 `base_url`、`api_key`、`model` 即可。

## 配置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `api_mode` | `images` | `images` = OpenAI 图片协议；`chat` = 对话协议（图片在回复里） |
| `base_url` | `https://api.openai.com/v1` | 一般以 `/v1` 结尾 |
| `api_key` | 空 | 必填 |
| `extra_keys` | 空 | 备用 Key，一行一个，遇 429 自动轮换 |
| `model` | `gpt-image-1` | 厂商文档里的模型 ID |
| `size` / `size_square` / `size_landscape` / `size_portrait` | `720x720` / `720x720` / `1280x720` / `720x1280` | 按用户说的「横屏/竖屏/方图」自动选 |
| `max_canvas` | `1280x720` | **画布上限**，超过就等比缩小；填 `off` 关闭 |
| `timeout` | `180` | 单次请求超时（秒） |
| `max_retries` | `2` | 只对 429、5xx、网络错误重试 |
| `cooldown_seconds` | `20` | 单用户冷却，防连点扣费，0 关闭 |
| `max_concurrent` | `2` | 全局并发，超出排队 |
| `daily_quota` | `0` | 每人每日张数，0 不限（额外限制，与额度池取更严的） |
| `global_daily_quota` | `5` | **额度池大小**，默认全站每天共 5 张 |
| `quota_scope` | `site` | 额度池作用范围：`site` 全站 / `group` 每群 / `user` 每人 |
| `auto_detect` | `true` | 不开指令也能识别「画图/生图」意图 |
| `extra_trigger_words` | 空 | 自定义触发词，逗号分隔 |
| `prompt_engine` | `astrbot` | `astrbot` 复用已配好的对话模型 / `custom` 单独填对话 API / `off` 直接出图 |
| `artist_level` | `balanced` | 画师主动性：`obedient` 照做 / `balanced` 风格自定 / `assertive` 主导 |
| `artist_persona` | `有个人风格的插画师` | 拼进提示词的人格，可换成摄影师、概念设计师 |
| `remember_last` | `true` | 记住这个用户上一张画，可延续或刻意换风格 |
| `llm_provider_id` | 空 | 指定用哪个对话模型（留空 = 当前默认） |
| `llm_base_url` / `llm_api_key` / `llm_model` | DeepSeek 默认 | `custom` 模式下使用 |
| `llm_temperature` | `0.7` | 构思温度，0.5~0.9 较合适 |
| `llm_timeout` | `25` | 超时立即退回原话出图 |
| `show_thought` | `false` | 是否把模型的构思过程发出来 |
| `reply_with_prompt` | `true` | 图片上方附带提示词 |

## 提示词引擎（Agent 协作）

这里不是训练模型，是**两个模型分工**：对话模型负责想，生图模型负责画。

```
用户原话「画只猫在月球上钓鱼」
      ↓
对话模型：补主体外观、镜头、光线、色调，输出结构化 JSON
      ↓
生图模型：拿这段完整描述出图
```

实际差多少，看同一条需求的两种结果：

| 模式 | 发给生图模型的提示词 |
|---|---|
| 关闭 | `猫在月球上钓鱼` |
| 开启 | `一只橘色虎斑猫坐在灰白色月壤上，前爪握着细长钓竿，钓线垂向星空；背景是巨大的蓝色地球，环形山投下长影；广角低机位，冷蓝主光加地球反光，电影级质感，超清细节` |

对话模型的输出被约束成 JSON，多一层容错：遇到带 ```json 代码块、前后夹解释、甚至直接吐一段散文，都能正确取出提示词。

```json
{
  "thought": "补上低重力、地球反光、广角低机位，让它有科幻感而不是普通插画",
  "prompt": "一只橘色虎斑猫坐在灰白色月壤上……",
  "negative": "模糊, 变形的手, 多余肢体, 水印, 低质量"
}
```

`thought` 是模型的构思，`prompt` 才是给生图模型的，`negative` 会以 `Avoid: …` 追加。三者分开的好处是：构思可以展示给用户看，但不会污染提示词。

### 三种接法

| 配置 | 适用 |
|---|---|
| `prompt_engine: astrbot`（默认） | 已经在 AstrBot 里配了 DeepSeek / GPT / 通义，直接复用，**不用再填 Key** |
| `prompt_engine: custom` | 想单独用更便宜的小模型做改写，填 `llm_base_url` / `llm_api_key` / `llm_model` |
| `prompt_engine: off` | 不需要构思，省掉这一次调用 |

### 让它像个画师，而不是传声筒

默认的提示词工程师会老老实实执行「画只猫」，画出来就是一只标准的猫。如果你要的是**有主张的画师**，调 `artist_level`：

| 等级 | 它会怎么做 | 适合 |
|---|---|---|
| `obedient` | 严格按你说的画，只补你没说的细节 | 电商图、素材图，要可控 |
| `balanced`（默认） | 风格、构图、视角、光线它自己定，但不改你要的东西 | 日常用，兼顾可控和好看 |
| `assertive` | 它是主导者，可以改构图、风格、情绪基调，只保留你点名的主体和用途 | 想要惊喜、做创作 |

三档的差别就写在系统提示词里，模型真正读到的是这几句：

> **obedient**：以委托人的描述为准，你只负责补全他没说的细节，不做方向上的改动。
>
> **balanced**：在满足委托人要求的前提下，风格、构图、视角、光线由你决定，不必征求同意。你可以在实现方式上和他想的不一样，但不能换掉他要的东西。
>
> **assertive**：你是这张画的主导者。委托人的描述只是起点，你可以改变构图、风格甚至情绪基调，只要保留他明确点名的主体、数量和用途。你要拿出自己的判断，而不是执行订单。

用户只说「画猫」，`assertive` 下的实际输出：

```
🎨 我想这么画：
他只说了猫。我不想画那种蹲在窗台上的标准猫，我想画它刚睡醒、
还没完全站起来的一瞬间——有点狼狈，但很真实。
· 改成俯拍，让它显得小
· 用清晨的侧逆光切进画面
· 背景压成几乎全黑的室内

正在画，稍等…
```

交给生图模型的是：

> 一只狸花猫刚从纸箱里爬出来，前爪还踩在箱沿上，身体半伸半缩；清晨侧逆光从左侧窗户切进来，尘埃在光里悬浮；背景是几乎全黑的室内，只隐约见木地板纹理；俯拍，浅景深，胶片颗粒感

**它的自由是有边界的**：主体、数量、画面文字、指定颜色、用途，一条都不许改。它改的是「怎么画」，不是「画什么」。这条写死在系统提示词里，等级再高也不会越界。

想换个身份，改 `artist_persona`：

```
偏爱胶片质感的街头摄影师
做暗黑奇幻设定的概念设计师
给独立乐队画封面的版画家
```

### 画师会记得上一张

`remember_last` 开启时（默认），同一个用户再画，系统会把他上一版的构思和提示词一起带进去，并明确要求：

> 要么延续这个方向，要么明确地换个路子——不要含含糊糊地重复上一版。

所以「再来一张」不会得到两张几乎一样的图，也不会突然跳成完全不相干的风格。

### 不会拖垮出图

| 情况 | 行为 |
|---|---|
| 对话模型超时（默认 25 秒） | 立刻退回原话出图 |
| 接口报错 / Key 无效 | 退回原话，日志留一行 |
| 连续失败 3 次 | 熔断 5 分钟，期间直接出图，不再重试 |
| 同一句需求重复画 | 命中缓存，不重复调用 |

所以最坏情况就是退化成「没有引擎」的老行为，不会出现画不出图。

### 成本

一次改写约 300~600 token。按 DeepSeek 的价格算，**每次生图多花 0.001~0.002 元**，相对一张图 0.06~0.3 元可以忽略。开启缓存后同句重画不再计费。

### 关于「训练」

如果你想要的是**模型越来越懂你的口味**，那要的是微调，不建议现在做：训练数据太少（几百张才刚起步）、换一个生图模型就失效、成本远高于收益。更划算的做法是**记住偏好**而不是训练权重：现在已经有 `remember_last` 记住上一张，`artist_persona` 固定人格，`prompt_suffix` 固定画风词。再加一层「记住这个风格」也不难——把用户说过的偏好存进 KV，下次自动带上，效果比微调更直接可控。


## 画布与额度

**画布**是双保险，不是只靠请求参数：

1. 请求时按 `size_*` 下发，默认就是 720p 档（`720x720` / `1280x720` / `720x1280`）；
2. 有些模型只认固定尺寸（如 `gpt-image-1` 只接受 `1024x1024`），插件会自动去掉 `size` 重试一次，用厂商默认值；
3. 拿到图后统一过一遍 `_fit_canvas`，超过 `max_canvas` 就等比缩小。

所以不管是哪家模型、返回多大的图，落到磁盘上的文件一定不超过 1280×720。

**额度**按自然日重置（0 点清零）。`global_daily_quota` 是池子大小，`quota_scope` 决定这个池子按什么粒度分：

| 想要的效果 | 怎么配 |
|---|---|
| **全站每天共 5 张（默认）** | `quota_scope: site` + `global_daily_quota: 5` |
| **每个 QQ 群各自 5 张** | `quota_scope: group` + `global_daily_quota: 5` |
| 每人每天 5 张，跨群累计 | `quota_scope: user` + `global_daily_quota: 5` |
| 每群 5 张，且每人最多 2 张 | `quota_scope: group` + `global_daily_quota: 5` + `daily_quota: 2` |
| 完全不限 | `global_daily_quota: 0` 且 `daily_quota: 0` |

`quota_scope` 的三种取值：

- **`site`（默认）**：所有群、私聊共用一个池子。A 群画了 3 张，B 群和私聊加起来只剩 2 张。
- **`group`**：每个群独立一个池子，带群号记账；私聊没有群号，按会话各自独立。
- **`user`**：每个用户独立一个池子，同一个人换群也共用自己那 5 张。

`/生图状态` 会按范围显示「今日剩余：全站 3 / 5」「今日剩余：本群 3 / 5」或「今日剩余：你 3 / 5」。额度只在**成功出图后**才扣，失败和视频请求都不计。

## 各厂商怎么填

| 服务 | base_url | model 示例 | api_mode |
|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-image-1` | images |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Kwai-Kolors/Kolors` 等 | images |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `cogview-4` | images |
| one-api / new-api 中转 | 你的中转地址 + `/v1` | 中转支持的模型 ID | images |
| Gemini 兼容层 / 只开对话接口的聚合站 | 对应地址 | 对应模型 ID | chat |

> 模型 ID 与尺寸限制以厂商文档为准。若模型只支持固定尺寸，插件会自动回退并靠本地压缩保证 720p 上限，一般不用手动改。

## 常见问题

**能生成视频吗？**
不能，本插件只做静态图片。「生成一段视频」这类请求会被直接拦下，也不会产生 API 费用；视频请用专门的视频插件。

**说了「画只猫」没反应？**
1. 确认 `auto_detect` 开着；
2. 确认当前人设没有禁用工具（用 LLM 工具调用时需要）；
3. 看日志里有没有 `[astrbot_plugin_astro_painter]` 的 WARN；
4. 把「画图」加进 `extra_trigger_words` 也行。

**返回 400 / 401 / 404？**
插件会把厂商原文带出来：401 查 Key，404 查 `base_url` 是否少了 `/v1`，400 多半是模型名或尺寸不支持。

**群里太吵？**
`auto_detect` 关掉，只保留 `/画图`；或把 `cooldown_seconds` 调大。

**图片存在哪？**
`AstrBot/data/plugin_data/astrbot_plugin_astro_painter/`，按时间戳命名，可定期清理。

## 发布到插件市场

1. 改 `metadata.yaml`：`author` 换成你的 GitHub 用户名，`repo` / `social_link` 换成你的仓库地址；确认 `name` 与仓库名、目录名一致。
2. 推到公开 GitHub 仓库（根目录就是插件目录，不要多套一层文件夹）。
3. 打开 <https://cloud.astrbot.app/publish>，登录后提交仓库地址。
4. 要求：zip ≤ 16MB；不要提交 `__pycache__`、`.git`、测试产生的图片（`.gitignore` 已处理）。

市场会按 `metadata.yaml` 展示名称、简介、标签和支持平台。

## 隐私与费用

- API Key 只存在 AstrBot 本地配置里，不会外发。
- 提示词与用户发送的参考图会发给你配置的模型服务商，请自行确认合规与内容审核要求。
- 每张图都会产生费用；`global_daily_quota` 与 `cooldown_seconds` 是成本闸门，建议保持开启。
